# Repository working rules

- Run validation and acceptance tests as part of the requested work without a separate permission question. This includes local browser interaction tests, screenshots, resizing, and visual or animation checks. Use demo mode or isolated test fixtures for scripted outcomes.
- Do not create or maintain `RELEASE.md` in this repository for now. This repository rule overrides planning-skill defaults that require a release manifest. Keep implementation and acceptance evidence in the active plan and the existing index/TODO; do not introduce a substitute release/status file.
- Keep deployment and publication separate from local testing. Use an explicit deployment request before changing the hosted Site.
